# Feature Prioritization — MoSCoW

## Must Have — شرط عرضه MVP

| ID | قابلیت | معیار مختصر |
|---|---|---|
| M01 | حساب، خانواده و نقش‌ها | جداسازی کامل داده خانواده‌ها |
| M02 | پروفایل ذائقه و قواعد | منع قطعی و ترجیح نرم تفکیک شوند |
| M03 | موجودی دستی | مقدار، واحد، محل و وضعیت اطمینان |
| M04 | بانک رسپی ایرانی | مواد و مراحل ساختاریافته |
| M05 | سه پیشنهاد غذا | زمان، بودجه، تاریخچه و موجودی لحاظ شود |
| M06 | گردونه هوشمند | فقط گزینه‌های واجد شرایط |
| M07 | رسپی و جلسه آشپزی | مراحل، تایمر و ثبت پخت |
| M08 | تقسیم کار ساده | پیشنهاد قابل ویرایش وظایف |
| M09 | برنامه هفتگی | ساخت، جابه‌جایی و لغو وعده |
| M10 | لیست خرید مشترک | تجمیع و کسر موجودی |
| M11 | Voice/Text AI | Transcript، تأیید و پاسخ متنی/صوتی اختیاری |
| M12 | Link-out فروشگاهی | لینک معتبر یا لینک جست‌وجو |
| M13 | PWA و آفلاین پایه | فهرست و رسپی ذخیره‌شده |

## Should Have — پس از پایدارسازی هسته

- ورود صوتی مستقیم موجودی.
- بارکد.
- استخراج فاکتور و اسکرین‌شات با تأیید اجباری.
- هشدار انقضا و اتمام موجودی.
- گزارش بودجه و تنوع غذایی.
- مقایسه محدود فروشگاه‌ها با برچسب زمان مشاهده.
- اشتراک Premium با Feature Flag.

## Could Have — فاز توسعه

- عکس یخچال و تشخیص احتمالی اقلام.
- استخراج رسپی از URL یا تصویر غذا.
- پیش‌بینی زمان پایان موجودی.
- تاریخچه قیمت مبتنی بر مشاهدات ثبت‌شده.
- مأموریت و بازی‌سازی خانوادگی.

## Won’t Have در MVP

- پرداخت داخل محصول.
- انتقال خودکار سبد میان فروشگاه‌ها.
- مدل ML اختصاصی.
- تحلیل کامل ویدئو.
- نسخه درمانی شخصی‌سازی‌شده.
